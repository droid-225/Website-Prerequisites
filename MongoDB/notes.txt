Part 2: Databases
[Note: Part 1 was just the setup]

Basic database structure:
1. document: singluar entity / object in the database
2. collection: a collection of documents, like a row in a relational database
3. database: a collection of collections

exit: Exits mongosh
cls: Clears screen
show dbs: Shows all Databases.
use databaseName: Switches to specified database, if database given does not exit, a new empty database with that name is created.
    -> Empty databases will not show up in the list of databases.
db.createCollection("collectionName"): Creates a new collection in the active database
db.dropDatabase(): Deletes (drops) the active database
    -> Creation and deletion of databases can also be done using Compass

Part 3: Insert

db.collectionName.insertOne({field:value, ...}): Creates a single new document in the specified collection with one or more field:value pairs.
db.collectionName.find(): Shows all documents inside the specified collection.
db.collectionName.insertMany([{field:value, ...}, {field:value, ...}, ...]): Creates multiple new documents in the specified collection with one or more field:value pairs.
Same stuff can be done in Compass (use format button (the right most bookshelf looking button) if it a warning pops up during creation)

Part 4: Data Types

String: Series of text in quotes, can contain alphabets, spaces, and numbers
Integer: Whole numbers
Double: Decimal numbers
Boolean: True or false
Date: Dates
    -> Syntax: dateVariableName: new Date()
    -> If Date() is left empty, it returns the current date and time in UTC
    -> Otherwise a date can be specified, e.g. "2025-08-14T00:00:00"
Null: No value
Arrays: A collection of values
    -> Syntax: arrayVariableName: ["value1", "value2", ...]
Nested Document: Document within a document

Part 5: Sorting and Limiting

Chaining the .sort() method like this:
db.collectionName.find().sort({fieldName:value})
can be used to sort documents in a collection based on the specified field and a given value
e.g. 
.sort({name:value}) would sort the name field either,
    -> if value = 1, in alphabetical order
    -> if value = -1, in reverse-alphabetical order

.sort({gpa:value}) would sort the gpa field either,
    -> if value = 1, in ascending order
    -> if value = -1, in descending order

Chaining the .limit() method like this:
db.collectionName.find().limit()
ca be used to return a specified number of documents from a collection.
e.g.
.limit(1) returns the first document
.limit(3) returns the first 3 documents

.sort({}) and .limit() can also be chained consecutively

Part 6: Find

The find method also has the following parameters:
.find({query}, {projection})
-> query is can be used to find documents with one or more specific field values (comma sepearated)
    -> e.g. .find({name:"XXXXX"}) returns only those documents with the given name value
    -> e.g. .find({name:"xxxxxx", gpa:xxxxx}) returns only those documents with the given name and gpa values
-> projection is used to return only certain fields from the documents in the collection
    -> e.g. .find({}, {name:true}) returns only the names and ids of each document in the collection 
    -> id is true by default, and needs to be manually set to false if not needed in this parameter
    -> multiple parameter values can also be chained here
        -> e.g. .find({}, {_id:false, name:true}) only returns the name values of each document

Part 7: Update

We can concatenate the following methods to db.collectionName:

.updateOne({filter}, {update}) : Used to update single document
-> filter: Selection criteria, usually better to filter by object id if a specific document needs to be updated
-> update: Update function to be executed
    -> $set:{fieldName:value} : Either adds or replaces specified field to/in the filtered document
    -> $unset:{fieldName:""} : Removes specified field from document

.updateMany({filter}, {update}) : Used to update many documents
-> filter: Can be left empty here to select all documents
    -> fieldName:{$exists:true/false} : Filters the documents that either do or do not have the specified field
-> update: Update function applied to all filtered documents

Part 8: Delete

We can concatenate the following methods to db.collectionName:

.deleteOne({query}) : Deletes the document that satisfies the query

.deleteMany({query}) : Deletes documents which satisfy the query

the $exists can also be used in the queries here to delete documents which either do or do not have a specified field. 

Part 9: Comparison Operators

Operators:
-> $ne: Not
    -> db.collectionName.find({fieldName:{$ne:value}})
    -> Returns all documents that do not have the specified field value

-> $lt: Less than
    -> db.collectionName.find({fieldName:{$lt:value}})
    -> Returns all documents that have a field value less than the specified value

-> #lte: Less than or equal to
    -> db.collectionName.find({fieldName:{$lte:value}})
    -> Returns all documents that have a field value less than or equal to the specified value

-> #gt: Less than or equal to
    -> db.collectionName.find({fieldName:{$gt:value}})
    -> Returns all documents that have a field value greater than to the specified value

-> #gte: Less than or equal to
    -> db.collectionName.find({fieldName:{$gte:value}})
    -> Returns all documents that have a field value greater than or equal to the specified value

You can use combinations of these opeartors too
e.x.: db.collectionName.find({fieldName:{$gte:lowerValue, $lte:higherValue}})
-> Returns documents with field values that are between the lower and higher values

-> $in: In
    -> db.collectionName.find({fieldName:{$in:[//array of values]}})
    -> Returns documents with field values that match those in the array

-> $nin: Not in
    -> db.collectionName.find({fieldName:{$nin:[//array of values]}})
    -> Returns documents with field values that do not match those in the array

Part 10: Logical Operators

-> $and
    -> db.collectionName.find({$and: [{//conditonal operator 1}, {//conditonal operator 2}, ..., {//conditonal operator n}]})
    -> Returns documents that pass all the conditionals in the conditonal operator array

-> $not
    -> db.collectionName.find({fieldName: {$not: {conditionalOpeartor:value}}})
    -> Returns documents that do not pass the conditional operator
    -> Also returns documents with null values for the specified field

-> $nor
    -> db.collectionName.find({$nor: [{//conditonal operator 1}, {//conditonal operator 2}, ..., {//conditonal operator n}]})
    -> Returns documents that do not pass all of the conditionals in the conditonal operator array

-> %or
    -> db.collectionName.find({$or: [{//conditonal operator 1}, {//conditonal operator 2}, ..., {//conditonal operator n}]})
    -> Returns documents that pass any of the conditionals in the conditonal operator array

Part 11: Indexes

Using indexes, we are storing our data as a B-Tree

Note: Chaining a query with .explain("executionStats") also returns stats about the execution of the query.
-> The query performes a linear search when finding documents based on certain criteria
-> This can take a long time with larger databases
-> Instead we can speed the search time up using indexes

.createIndex(): Creates an index for documents in a collection based on specified criteria or order
-> e.g. db.students.createIndex({name: 1}) make an inndex based on the names in ascending order

An index is just a value we can use to more easily find certain values.
The object id "_id_" is a default index

.getIndexes(): Returns all the indexes we can use for the given collection
e.g. db.students.getIndexes() returns all the indexes we can use for the students collection

.dropIndex("indexName"): Removes the index with the specified name

Using indexes is useful when doing searching, not so much during updating

Part 12: Collections

show collections : shows all collections in a database

The .createCollection() method has some fields:
db.createCollection("collectionName", {capped:true, size:10000000, max:100}) : Sets a maximum memory size (size)[in bytes] and a maximum document count (max).
-> capped can either be true or false

db.createCollection("collectionName", {autoIndexId:true}) : Sets whether an automatic index Id is set for the collection.
-> autoIndexId can either be true or false

db.collectionName.drop() : Removes the specified collection
